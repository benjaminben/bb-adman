## Rules for these slices

- **The name rule.** Where a visible label gets shorter, the control keeps its old accessible name when the new visible words are part of it (for example "Test" shown, "Test connection" as the name). This keeps the tests and the end-to-end helpers that find things by name. Each slice says which names change; any name not listed stays as it is.
- **Hidden words for marks.** A mark that replaces words keeps those words for a screen reader: as the StatusMark's tip (its visually hidden copy), or as visually hidden text beside an icon. Tests that find the old words by text keep working; a slice says where they do not.
- **Live lines that become marks** keep their words in a visually hidden `role="status"` region, so a screen reader still hears the change. Failures, "Cancelled." and every line the plan's security rule names stay visible.
- **Section ids** are `'{screen}.{section}'`: `settings.keys`, `settings.comfy`, `props.type`, `props.box` and so on, as each slice names.
- **Older shots files** (`tests/shots/*.shots.ts` not named `dw-*`) are not part of any check. A slice does not edit them, except the shared step files it names. A picture that no longer matches the screen is left for the orchestrator.
- **Words on screen** before and target come from the design audit; each report gives the measured count.
- **Exit check, all slices:** `npm run lint`, `npm run typecheck`, the vitest folders named, `npm run build`, the named end-to-end specs, then the slice's shots file. The full gate runs once after Wave 2.
