### P7-3 — FFmpeg fetch script and test clips

- **Exists when done:** `npm run fetch:ffmpeg` puts a licence-checked LGPL FFmpeg at `resources/ffmpeg/{platform}-{arch}/ffmpeg[.exe]`; on this Mac it has run once; two tiny test clips made with it are committed.
- **New files:** `scripts/ffmpeg/fetch.mjs` (entry), `sources.mjs` (reads and checks `ffmpeg-sources.json`), `download.mjs`, `build-mac.mjs`, `licence-check.mjs`, `make-fixtures.mjs`; `scripts/ffmpeg-sources.json`; `tests/fixtures/video/tiny.mp4` (1 s, 64 × 64, H.264, no sound) and `tiny-sound.mp4` (the same with an AAC track), each under 50 KB.
- **May touch:** `package.json` (one script, `"fetch:ffmpeg": "node scripts/ffmpeg/fetch.mjs"`; it is never run by `install`, `postinstall` or `npm ci`); `eslint` or `tsconfig` include patterns if `scripts/` is not linted today (report it).
- **`ffmpeg-sources.json`:** `{ version, windows: { url, sha256, member }, source: { url, sha256, configure: [...] } }`. `url` is `https:`; its host is in the script's fixed list (the builder's release host and its download host, and the FFmpeg project's download host); `sha256` is 64 hex digits; `member` is a relative path with no `..` and no leading `/`. The developer picks a dated LGPL win64 release of the public builder OI-09 names and the matching FFmpeg release source archive, downloads each once, and records address and SHA-256.
- **The script's rules:** downloads only over `https:` to listed hosts, following a redirect only to a listed host, at most 300 MB, into `resources/ffmpeg/.work/` (already ignored by git); checks the SHA-256 before unpacking; unpacks with the system `tar` run by `spawn` with an argument array and `shell: false`, extracting only the named member (Windows) or the source tree (macOS); on macOS runs `./configure` with exactly the `configure` list from the JSON and `make ffmpeg`, both by `spawn` with `shell: false`; copies the binary into place, sets mode 755; then runs the licence check (`phase-07.md`, "Where FFmpeg comes from") and deletes a binary that fails. The configure list is the one in `phase-07.md` plus `--enable-encoder=h264_videotoolbox,aac_at`, `--enable-indev=lavfi`, `--enable-filter=color,anullsrc` so the test clips can be made here (Phase 8 needs the encoders too). It never runs with an elevated account and installs no system software: if the build tools are missing it stops and says which.
- **Needs:** nothing.
- **Tests first:** `tests/unit/scripts/ffmpeg-sources.test.ts` (the committed JSON passes; a table of bad values each refused: `http:`, an unlisted host, a short hash, `../x`, `/abs`); `tests/unit/scripts/ffmpeg-licence-check.test.ts` (sample `-L` and `-buildconf` texts: LGPL passes; GPL, `--enable-gpl` and `--enable-nonfree` fail); `tests/unit/scripts/ffmpeg-download.test.ts` (with a stand-in `fetch`: a redirect to an unlisted host refused, an oversize answer stopped, a wrong hash refused and the file deleted).
- **Hand run:** `npm run fetch:ffmpeg` once on this Mac; report the first line of `-version`, the licence check result and the binary size. Then `node scripts/ffmpeg/make-fixtures.mjs` makes the two clips (the only place the binary is run with `-f lavfi`); report their sizes. The Windows binary's licence check is the stakeholder's (D-087).
- **Exit check:** lint, typecheck, `npm test`, the hand run.
- **Class:** A plus the hand run. **Security:** full (downloads and runs a program). **Size:** medium.
