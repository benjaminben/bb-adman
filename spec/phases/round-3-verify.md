# Round 3: what to verify

Assumptions made while building the stakeholder's round 3 notes (2026-11-22), for him to confirm or change. The rulings are D-103 and D-104 in `DECISIONS.md`.

1. **Dropdown arrow.** Every dropdown now draws the app's own arrow with room to its right. Built in `ui/base.css`.
2. **Shipped ComfyUI workflows are proven (D-103).** Six become `proven`: the three MiniMax H3 video workflows, MOSS-Image from a prompt, FLUX with reference pictures, the BiRefNet cut-out. The two MOSS-Image workflows for reference pictures and extend stay `draft`: their graphs are stand-ins no server can run. The BiRefNet cut-out has not had a real run yet (the test server lacked the model file).
3. **Custom workflows are kept per computer, not per project (D-104). Confirmed by the stakeholder (2026-11-22): they are part of the user's settings, like API keys.** A project or package never carries one. This reads "treat workflows like assets which are external files" as: picked from disk and copied into the app's own folder. The older draft requirements (per project, packaged with the project, marking inside the app, a warning when a person adds one) are not built.
4. **Marks.** A step's title starts with `adman:` followed by one or more of `prompt`, `seed`, `width`, `height`, `ref1` to `ref8`, `first-frame`, `frames`, `output`. The job is worked out from the marks; nobody picks it. No mark for a negative prompt or frames per second in this round.
5. **A person's add asks nothing.** No warning dialog; Settings shows one fixed line that the licence of the models is the person's own matter.
6. **An agent's add always asks**, lists every node type, and says the workflow can use any node on the server, "including nodes that read files on that computer, reach the internet or use paid services". No "don't ask again". An agent can list and run workflows but never read one back.
7. **Paid nodes on the server (accepted risk, please confirm).** A workflow can call a paid service from the ComfyUI server with keys kept there. Once added, an agent may run it under the ComfyUI tick, which the app otherwise treats as free. The ask dialog names this; nothing else limits it.
8. **Limits and defaults.** At most 50 workflows; a file at most 2 MiB and 500 nodes. Defaults a person can change in Settings: pictures about 1 megapixel, video about 0.4 megapixel, 24 frames a second, clips up to 5 seconds. A workflow takes exactly as many reference pictures as it has `ref` marks.
9. **Changing a workflow** means removing it and adding the new export; the app does not watch the picked file. Removing one makes runs that have not started fail; runs already sent go on.
10. **The remembered workflow choice** is per computer and per job kind.
11. **Translations tab.** Rows follow the Variants tab's order; each language starts with a larger heading; a first "Source" block edits the primary language's words. An edit there changes that one post. A linked post of another size in the same language keeps its old words until Sync, by the usual link rule; its translations read "Out of date". Undo for a source edit is on that post's own undo list, as in the editor, not on the campaign's Undo button. An edit never starts a translation run.
12. **Model names.** Wherever the app names an AI service, it now names the model too, as "service · model": "Google Gemini · Nano Banana 2.1", "fal.ai · Seedance 2.0", "ComfyUI · MOSS-Image" (for ComfyUI, the model of the workflow in use). Please check:
    - (a) Gemini's layout and text jobs read "Google · Gemini 3.5 Flash-Lite", because a word is never said twice. The other choice is "Google Gemini · Gemini 3.5 Flash-Lite".
    - (b) The tool descriptions an agent reads name each model and its model ID. The job status an agent reads still names neither the service nor the model. A security test holds that; changing it needs your word.
    - (c) In the run dialog the service buttons now have two lines, so they are taller.
13. **Custom workflows, as built.** Please try:
    - (a) Settings, "ComfyUI workflows": add an API-format export with `adman:` titles, change its name and sizes, remove it.
    - (b) The run dialog: with ComfyUI chosen and two or more workflows that fit, a "Workflow" select appears; the pick is remembered per job kind. It never appears on a retry (a ComfyUI retry starts at once with the workflow the first run used).
    - (c) An agent's `add_comfy_workflow`: the dialog shows the name, what it makes and every node type; "Add" works only once the list is on screen; there is no "don't ask again". A taken name or a full list (50) is refused before you are asked.
    - (d) The server check in Settings lists an added workflow as "Added" with the node types the server lacks. A run that fails for that reason shows only a count ("The server is missing 1 thing this workflow needs. Press Check in Settings to see them."), because job rows travel with the project.
14. **Small rulings made at the build (change any you dislike).**
    - (a) Size choices for an added workflow: 0.25, 0.4, 0.5, 1, 2 and 4 megapixels.
    - (b) A node or an input named `__proto__`, and a link whose number is not a whole number, are refused at add.
    - (c) A second file with a taken name is saved as "{name} 2" for a person; an agent's add with a taken name is refused.
    - (d) With no shipped workflow for a job, the oldest added one that fits is the default.
    - (e) The picker lists every added workflow that fits the job, also one whose reference-picture count differs from the pictures ticked; that run is then refused with "This workflow needs {n} reference pictures."
    - (f) An added workflow can be saved with video numbers that never give a clip (for example 1 frame a second, 1 second, frame offset 5); each run then stops before anything is sent. Not refused at add yet (`review-leftovers.md`).
15. **Proof on the real server.** One custom workflow run was made on the ComfyUI test server (the shipped Flux graph, marked with `adman:` titles by the test, one reference picture): it passed in 31 seconds. Everything else was tested against a stand-in server. Your own exported workflows have not been tried; that is the thing to test first.
16. **A run made with an added workflow** reads "ComfyUI · {workflow name}" in Activity and in failure lines; one whose workflow was removed since reads "ComfyUI · Custom workflow".
17. **An added workflow runs with 1 picture up to its number of `ref` marks** (your ruling, 2026-11-22). The app takes the unused picture steps out of the graph it sends. This works when the unused pictures feed optional inputs (as in the MOSS edit step). If a workflow's steps cannot run without a picture, the server refuses that run; give it every picture, or tell me and I will add a way to say so in the marks.
18. **An agent can read and change a campaign's directions (D-105; your words: "Need an MCP skill for read/write directions within a campaign").** Reading is `get_campaign`, as before. Three new tools: `create_direction` (a copy of a master becomes a new direction, no ask), `rename_direction` (no ask; you can undo it) and `delete_direction` (asks you on screen like the other deletes; "Don't ask again for deletes" covers it; no undo). Please confirm that adding and renaming need no ask. Agents still cannot fan out or sync.
19. **Brand in a brief: what is kept** (`spec/brief-brand.md`). The stored brief keeps the layout, art direction, ad sets choice and colours. The logo and fonts are kept only as files of the project, never as paths.
20. **Brand colours colour the text (my ruling; change it if you dislike it).** The brief's colours replace the campaign's colour rules. The starting layouts write text in white or near black, which the colour check would then flag at once. So each text of the first ad takes the nearest brand colour (white becomes the lightest brand colour, and so on). A brand list with no light colour, or no dark one, can leave text hard to read; you recolour it in the editor. The other choices were to leave the flags, or to add the layout's own text colours to the colour rules.
21. **Fonts.** The headline font goes on the headline only; the other font on every other text. If a brief gives only one, the rest keeps the default font. A brand font is not shared on publish until you tick "I am allowed to share this font".
22. **The brief form.** A new folded section "Brand and layout" shows the layout (a choice of the five), the art direction, the logo, the colours and the fonts, each with a remove button. It adds no files of its own: other brand files are set after the campaign is made. A bad value is left out with a note, as a bad photo is.
23. **Agents and brand files.** An agent's brief names the logo and fonts by asset ID only. A path is refused and the agent is told to import the file first with `import_assets` (which asks you). Bad colours, layout or ad sets values are refused with the field named.
24. **One set of ads per subject.** `adsPer: subject` makes one direction per subject, named after the subject, each starting with its own ad of that subject. The form shows "Ad sets: Together | Per subject" when there are two or more subjects.
25. **Art direction in the prompt.** It goes into the first picture or video prompt of each ad as "Art direction: …", between the subject sentence and the last sentence. You can still edit the prompt before a run.
26. **The name "Make variants" (D-108).** The button reads "Make variants…", the dialog "Make variants of {direction}", the tile's item "Make variants from this one…". An agent that asks is told "Agents cannot make many variants at once in this version", since it can still add one variant. The command and file names inside the code keep "fan-out".
27. **Boxes in a new size: two paths, chosen per box (`spec/make-variants.md`).** A box still exactly where the master's starting layout put it goes where that layout puts it at the new size. Any box you moved keeps its distance to the nearer edges instead. So your 1:1 "photo-bottom-left" ad gives a 16:9 ad with the logo, headline and button on one left margin, and an ad you moved by hand keeps your margins. The app tells which layout an ad uses by where its boxes sit, so this works for ads made by an agent or a later direction too.
28. **A wide text box stretches.** A text box that spans most of the width (both side gaps smaller than the box) stretches to the new width; a picture never stretches, so a photo is not cut differently. Distances are measured against the shorter side of the ad, so 1:1, 4:5, 9:16 and 16:9 at 1080 keep their pixel margins.
29. **Text that fits.** In a new size or language, the text keeps the master's size (scaled with the shorter side) unless its box got tighter or its words changed; then it gets smaller until the app's estimate says it fits. It never gets bigger than the master's. When a translation run first fills a text, the size is checked once more and only ever made smaller. A translation you or an agent type is not resized; the "Text does not fit" mark tells you.
30. **A fitted size is the variant's own.** When it differs from the master's, it counts as changed on that variant, like a language's own font. So if you later change the master's headline size, the sync review offers it with "Keep mine" chosen; the rest of the style still syncs as before.
31. **Make variants from a variant.** The new variants start from that variant's words, boxes, pictures, look, and hidden or locked layers, and stay linked to the master (the only thing a variant can link to). They are out of date wherever the variant you picked was. Its own words go only to new variants in its own language; other languages are translated from the master's words, as usual.
32. **Videos.** Made from a video (the master's included), a new video variant copies its clips and sound settings. Before, a new video from a video master got only one clip from the background picture. Please confirm.
33. **Variants that already exist** at a chosen size, language and format are left as they are, and the dialog says how many. To redo one, delete it first.
34. **Cost.** Making from a variant costs the same as from the master and starts only after your click on "Make {n} variants" with the costs shown: a fill per size you set to "Generate fill", and a translation per language other than the main one and the picked variant's own. Copying itself calls no AI.
35. **The quickstart** drops its own layout pass (step 2.6) and uses the app's rule, so its ads match the app's.
36. **The colour picker (D-109).** A click on the colour you see, or on "+", opens the app's own picker: a square for saturation and brightness, a hue slider and the hex field. It replaces the system colour window, so macOS and Windows behave the same. One drag is one saved change and one Undo step. Please check it feels right.
37. **Assets on the home page (D-109).** The library (subjects, pictures, clips, fonts) is drawn inside the Assets block of the page, with "Import" and "New subject…" in its header. The side panel opens only from a campaign or the editor, and is not drawn on the home page.
